1. Giới thiệu
1.1 Mục tiêu
VTX là nền tảng điều phối chuỗi công việc kỹ thuật từ Jira đến Pull Request dự thảo với AI coding agents, kiểm thử độc lập, audit có thể truy vết và các cổng quyết định xác định. Mục tiêu là tự động hóa phần thao tác lặp lại, nhưng giữ quyền phê duyệt merge và triển khai production cho con người.
1.2 Trong phạm vi
Tiếp nhận webhook Jira, xác thực nguồn, đọc lại issue và deduplicate transition.
Đăng ký execution intent, task/run registry, state transitions, durable outbox và audit.
Scheduler, worker leasing/fencing, admission và giới hạn tác vụ đồng thời.
Git worktree lifecycle, môi trường cô lập và agent runtime Pi/OMP.
Trích xuất requirement, test baseline, coding, verification, QA độc lập.
Quality Gate dựa trên bằng chứng chính xác của commit SHA; retry có giới hạn; GitHub Draft PR.
Dashboard trạng thái, tiến độ và khả năng điều tra lỗi qua logs/evidence.
1.3 Ngoài phạm vi MVP
AI tự merge PR hoặc deploy production.
Chạy đồng thời quá 3 tác vụ coding được admit (giới hạn MVP mục tiêu).
Khẳng định chất lượng mã nguồn chỉ từ đánh giá chủ quan của một agent.
Ứng dụng mobile/desktop riêng; monorepo mới có Web UI.
1.4 Nguồn và độ chắc chắn
Các yêu cầu VTX-14, VTX-2 và VTX-3 dựa trên đặc tả đã thảo luận/chốt trong dự án. Phần VTX-4..13 được tổng hợp từ mục tiêu kiến trúc và phân chia epic; nhiều quyết định chi tiết chưa được đối chiếu với ticket gốc. Mọi mục gắn [PROPOSED] cần stakeholder phê duyệt trước khi coi là hợp đồng triển khai.

2.2 Mô hình logic
Jira Cloud → HTTPS Webhook Gateway → Go HTTP Intake → PostgreSQL Inbox/Execution Intent/Outbox → Task Registry &amp; State Machine → Scheduler → Worktree/Sandbox → Coding Agent → Verification → Independent QA → Deterministic Quality Gate → GitHub Draft PR → Human Review/Merge.
PostgreSQL lưu trạng thái bền vững và audit. Temporal phục vụ orchestration bền vững cho giai đoạn pipeline phù hợp; VTX-3 không tự chạy workflow Temporal. REST/SSE phục vụ giao tiếp với Web Cockpit.

3. Use cases và hành trình nghiệp vụ
UC-01 — Jira issue chuyển Ready to Dev
Jira phát webhook; gateway xác thực; service parse changelog; Jira API re-fetch; đối chiếu trạng thái/project; insert intent/outbox nguyên tử; trả disposition.
UC-02 — Webhook trùng hoặc issue thay đổi trạng thái
Replay cùng transition trả duplicate không tạo run; issue không còn eligible trả ignored/audit; re-entry transition mới được giữ là intent khác.
UC-03 — Task Run được admit
Consumer nhận intent; registry tạo run queued hoặc giữ deferred; scheduler cấp lease/admission tối đa 3 run coding đồng thời.
UC-04 — Coding và independent QA
Tạo sandbox/worktree; agent coding tạo commit; chạy verification; QA độc lập chấm chính xác SHA và đưa evidence.
UC-05 — Quality Gate và PR
Gate xác định PASS theo policy; chỉ khi đủ evidence mới tạo Draft PR; human review và merge riêng.
UC-06 — Lỗi, retry, cancel và khôi phục
Retry có budget; operator block/resume/cancel; worker crash không làm mất trạng thái/intent; stale lease bị từ chối.
UC-07 — Vận hành và quan sát
Operator xem trạng thái, timeline, evidence, dead-letter, outbox lag; xử lý redrive có audit.

9.2 End-to-end acceptance scenarios [PROPOSED]
E2E-01: Valid Ready-to-Dev Jira issue → one intent → queued run → admission → agent commit → independent QA PASS → Draft PR.
E2E-02: Same webhook delivered ≥3 times → exactly one resulting run and no duplicate PR.
E2E-03: Worker dies during coding; ownership/lease recovered without stale updates or duplicate side effects.
E2E-04: QA detects failure → no Draft PR; retries bounded and fully audited.
E2E-05: Commit SHA changes after QA → gate invalidates prior QA evidence.
E2E-06: Two or more runnable issues compete for 3 task slots; admission invariant preserved.
E2E-07: Operator cancel/resume and DLQ redrive follow permission policy and audit.

12. Definition of Done cho toàn bộ sản phẩm
Mọi functional MUST có test traceable và evidence gắn exact commit SHA.
Jira→PR end-to-end chạy với Jira/GitHub thật ở môi trường thử nghiệm có kiểm soát.
Không có đường auto merge hoặc prod deploy.
Không vượt admission limit; worker cũ không được ghi kết quả khi mất lease.
Toàn bộ event/state transitions có audit và recovery sau crash.
Security secrets, gateway, operator authorization và code sandbox được kiểm chứng.
Bất kỳ acceptance chưa đạt phải ghi BLOCKED/NOT VERIFIED, không tự đánh dấu PASS.
Ký duyệt SRS v1.0 sau khi xác nhận các open decisions.
